Agent system · private repository

Autonomous job-search agent

Eleven job boards, scanned every hour by Claude Code agents driving a signed-in Chrome. It writes the application, fills the ATS form, submits — and asks a human only what it genuinely cannot answer.

What it does

  • Scans on a cadence. Each board has its own interval and its own search URL, asserted before every scan: host, path and the filter params that must survive the redirect. A board whose search shape changed is skipped instead of silently returning nothing.
  • Only fresh work. Known links are never reopened; a newest-first list stops at the last scan or three seen cards in a row, and a job page opens only once its card has passed the fit rules.
  • Applies end to end. The sender writes a short message from CV facts only, then fills the external ATS form behind the board's own Apply button — Greenhouse, Ashby, Traffit, eRecruiter, Workable, Recruitee — and uploads the current CV.
  • Escalates instead of guessing. A question no rule answers becomes a Telegram poll; the answer is written back into the memory file and, if it generalises, proposed as a narrow reusable rule that a human approves with one tap.
  • Repairs its own searches. When a board's results collapse, a fix run diagnoses the breakage, merges only whitelisted search-parameter changes, verifies the candidate twice in separate read-only runs, and asks for approval before committing.

How it is built

  • The model never holds the authority. Limits, fit rules, the rate floor, deduplication and the final submit click live in code and hooks. A scanner agent runs with navigation and scrolling allowed and clicks, typing, scripts and file writes denied; the sender may click submit only after it has written a marker saying what it is about to send, and may append a tracker row only after a confirmation page.
  • Two browser layers, one tab. Primary is the Claude in Chrome extension; the DevTools Protocol is the fallback, chosen per hour by a precheck and logged. Every run works in a single tab of a separate Chrome profile and closes only the tabs it opened.
  • Durable orchestration. An n8n workflow generated from source — never edited in the UI — runs the hourly loop under a lock, with a gap scan that reaches back up to 48 hours after downtime, per-board caches of seen links, and a queue where anything undeliverable waits as a typed hold that expires on its own schedule.
  • Observable by design. Every run writes a list of what was sent, held, skipped and closed, with the cause; detection of empty scans, empty fields and below-median results runs in code, not in a prompt.

A run, in short

07:00 take lock · chrome precheck # extension up → run on it, CDP as fallback
      url check    # 11 boards: host, path, filters asserted
      scan djinni  # read-only agent, 18 cards, 3 pass the fit rules
      plan sends   # code: validate, dedupe, limits → 2 to send
      send         # message from CV facts, ATS form, submit
      record       # tracker rows, queue patch, telegram summary
      ...          # next board, then fix step, then release lock
